# Структура базы данных — Barbershop

## Назначение

Документ описывает логическую структуру данных учебной REST-системы барбершопа. Он не определяет механизм аутентификации, авторизации, хранение паролей или конкретную СУБД.

Пользователь содержит только базовые персональные данные. Профиль `Customer` позволяет создавать записи, а профиль `Employee` определяет работу пользователя в конкретном филиале. Пользователь и клиент не привязаны к филиалу.

## Состав данных

В системе выделены шесть основных сущностей:

- пользователь;
- клиент;
- сотрудник;
- филиал;
- услуга;
- запись.

## Сущности

### Пользователь (`user`)

Базовая информация о человеке в системе.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор пользователя | Да |
| `name` | Имя пользователя | Да |
| `phone` | Номер телефона | Да |
| `email` | Адрес электронной почты | Нет |

Ограничения:

- номер телефона уникален;
- адрес электронной почты, если указан, уникален;
- пользователь не связан с филиалом.

### Клиент (`customer`)

Профиль пользователя, который создаёт записи.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор клиента | Да |
| `user_id` | Идентификатор связанного пользователя | Да |

Ограничения:

- одному пользователю соответствует не более одного клиента;
- клиент не привязан к филиалу;
- клиент может одновременно иметь один или несколько профилей сотрудника.

### Сотрудник (`employee`)

Профиль работы пользователя в конкретном филиале. Сотрудник имеет внутреннюю роль в этом филиале.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор сотрудника | Да |
| `user_id` | Идентификатор связанного пользователя | Да |
| `role` | Внутренняя роль: `BARBER`, `MANAGER`, `ADMIN` | Да |
| `branch_id` | Филиал сотрудника; не заполняется для администратора | Нет |
| `specialization` | Специализация мастера; применяется для роли `BARBER` | Нет |
| `work_days` | Рабочие дни мастера в рамках недели | Нет |
| `work_start_time` | Начало рабочего времени мастера | Нет |
| `work_end_time` | Окончание рабочего времени мастера | Нет |
| `status` | Состояние сотрудника: `ACTIVE`, `INACTIVE`, `DELETED` | Да |

Ограничения:

- у пользователя может быть несколько профилей сотрудника — по одному для каждого филиала;
- пара `user_id` и `branch_id` уникальна;
- мастер и менеджер привязаны ровно к одному филиалу;
- администратор может не иметь привязки к филиалу;
- сотрудник, использующийся в записях, может быть логически удалён.
- рабочие дни и рабочее время заполняются для мастера.

### Филиал (`branch`)

Физический барбершоп, в котором оказываются услуги.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор филиала | Да |
| `name` | Название филиала | Да |
| `address` | Адрес | Да |
| `phone` | Контактный телефон | Да |
| `status` | Состояние филиала: `ACTIVE`, `INACTIVE`, `DELETED` | Да |

### Услуга (`service`)

Услуга, доступная в определённом филиале.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор услуги | Да |
| `branch_id` | Идентификатор филиала | Да |
| `name` | Название услуги | Да |
| `description` | Краткое описание | Нет |
| `price` | Стоимость услуги | Да |
| `duration_minutes` | Продолжительность в минутах | Да |
| `status` | Доступность: `ACTIVE`, `INACTIVE`, `DELETED` | Да |

### Запись (`appointment`)

Бронирование услуги пользователем у мастера на конкретное время.

| Атрибут | Описание | Обязательность |
|---|---|:---:|
| `id` | Уникальный идентификатор записи | Да |
| `customer_id` | Идентификатор профиля клиента | Да |
| `barber_id` | Идентификатор сотрудника с ролью `BARBER` | Да |
| `service_id` | Идентификатор услуги | Да |
| `branch_id` | Идентификатор филиала | Да |
| `starts_at` | Дата и время начала | Да |
| `status` | Статус записи | Да |

Возможные статусы: `NEW`, `CONFIRMED`, `COMPLETED`, `CANCELLED`, `NO_SHOW`.

Ограничения:

- сотрудник в поле `barber_id` имеет роль `BARBER`;
- мастер, услуга и запись принадлежат одному филиалу;
- мастер не может иметь две активные записи на пересекающееся время;
- запись не удаляется: отмена фиксируется статусом `CANCELLED`;
- завершённую, отменённую запись и неявку нельзя вернуть в рабочий статус.

## Доступность мастера и создание записи

Свободные слоты не являются самостоятельной сущностью. Они рассчитываются по графику и уже созданным записям мастера.

Мастер доступен для новой записи, если одновременно выполнены условия:

- дата входит в `work_days` мастера;
- время записи попадает между `work_start_time` и `work_end_time`;
- мастер, услуга и филиал имеют статус `ACTIVE`;
- у мастера нет пересекающейся записи со статусом `NEW` или `CONFIRMED`.

Продолжительность занятия определяется текущей длительностью выбранной услуги. Изменение стоимости или длительности услуги не сохраняется как отдельный исторический снимок в записи — это сознательное ограничение MVP.

Создание записи проверяет условия доступности и резервирует время как одну бизнес-операцию. Если другой запрос уже занял пересекающееся время, операция завершается конфликтом.

## Связи между сущностями

| Связь | Кардинальность | Смысл |
|---|---|---|
| `user` — `customer` | 1 : 0..1 | Пользователь может быть клиентом |
| `user` — `employee` | 1 : 0..N | Пользователь может работать в нескольких филиалах |
| `branch` — `employee` | 1 : N | В филиале работают мастера и менеджеры |
| `branch` — `service` | 1 : N | Филиал предлагает несколько услуг |
| `customer` — `appointment` | 1 : N | Клиент создаёт несколько записей |
| `employee` — `appointment` | 1 : N | Мастер выполняет несколько записей |
| `service` — `appointment` | 1 : N | Услуга может встречаться во многих записях |
| `branch` — `appointment` | 1 : N | В филиале проводится много записей |

```text
Пользователь 1 ─── 0..1 Клиент 1 ─── N Запись N ─── 1 Сотрудник (роль BARBER)
     │                                                                  │
     └──────────────────────────── 0..N Сотрудник ─────────────────────┘
                                      │
                                   Услуга ─── N ─── 1 Филиал
```

## Удаление и сохранность данных

- Удаление филиала, услуги или сотрудника допускается независимо от наличия записей.
- `DELETE` означает логическое удаление: статус сущности становится `DELETED`.
- Логически удалённые сущности не отображаются в актуальных каталогах и не участвуют в создании новых записей.
- Связи исторических записей с удалёнными сущностями сохраняются.
- Пользователи и записи не удаляются, чтобы сохранять историю и не нарушать связи.
