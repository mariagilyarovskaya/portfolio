# Barbershop — краткое описание проекта

## Назначение

REST-система для управления филиалами барбершопа, каталогом услуг, сотрудниками и онлайн-записями клиентов.

## Структура

- `User` — базовые персональные данные человека.
- `Customer` — клиентский профиль пользователя.
- `Employee` — профиль работы пользователя в конкретном филиале.
- `Branch` — филиал барбершопа.
- `Service` — услуга филиала.
- `Appointment` — запись клиента к мастеру на услугу.

## Модель данных

Пользователь может иметь один клиентский профиль и несколько профилей сотрудника — по одному для каждого филиала.

```text
User 1 ─── 0..1 Customer
User 1 ─── 0..N Employee ─── 1 Branch
Branch 1 ─── N Service
Customer 1 ─── N Appointment
Employee (BARBER) 1 ─── N Appointment
Service 1 ─── N Appointment
```

Роль сотрудника в филиале: `BARBER`, `MANAGER` или `ADMIN`. Пара `userId + branchId` уникальна для профиля сотрудника.

## Поведение системы

Клиент выбирает филиал, услугу, мастера и свободное время, после чего создаёт запись. Свободные слоты рассчитываются из рабочего графика мастера, длительности услуги и уже созданных записей.

Запись проходит статусы:

```text
NEW → CONFIRMED → COMPLETED
  └── CANCELLED
CONFIRMED → NO_SHOW
```

Две активные записи мастера не могут пересекаться по времени. Отмена записи изменяет её статус и не удаляет данные.

## Бизнес-правила

- мастер, услуга и запись относятся к одному филиалу;
- новая запись возможна только для активных мастера, услуги и филиала;
- время записи должно входить в рабочий график мастера;
- филиал, услуга и сотрудник удаляются логически: получают статус `DELETED`, а история записей сохраняется;
- цена и длительность услуги используются в текущем состоянии и не сохраняются отдельным снимком в записи.
